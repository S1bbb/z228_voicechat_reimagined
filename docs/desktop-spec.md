# ZALUPA228 Desktop — техническое задание (MVP, Windows)

Документ для агента-исполнителя. Всё, что нужно знать о проекте, решения заказчика и критерии готовности.
Где решение принято без заказчика, это помечено **[по умолчанию]**: менять можно, но с объяснением.

---

## 0. Коротко

Нужно десктоп-приложение для Windows на **Tauri v2 (Rust)**. Его окно показывает **наш веб-интерфейс, загружаемый
с сервера пользователя**, а Rust добавляет то, чего не умеет браузер:

1. **Глобальные горячие клавиши, которые работают поверх игры:** рация (зажал — говоришь), мьют, «оглушение».
   Поддерживаются клавиатура и **боковые кнопки мыши** (Mouse4/Mouse5).
2. **Звук рации:** тихий щелчок при нажатии и отпускании.
3. **Трей:** закрытие окна крестиком сворачивает в трей. Иконка показывает состояние (не в голосе / в голосе /
   говорю / мьют).
4. **Первый запуск:** человек вставляет **одну строку-приглашение** (адрес, порт, отпечаток сертификата,
   ключ доступа). Приложение проверяет, что сервер настоящий, и запоминает его.
5. **Автообновление** через GitHub Releases форка `S1bbb/z228_voicechat_reimagined`.

Голос, видео, чат, настройки звука и всё остальное уже работают в вебе. **Их не переписывать**: десктоп — это
оболочка вокруг сайта плюс «мост» между Rust и страницей.

Вне MVP (не делать, но не мешать будущему): оверлей в игре «кто говорит», автозапуск с Windows, Linux и macOS,
подпись кода сертификатом.

## 1. Что уже есть (контекст проекта)

Репозиторий: `S1bbb/z228_voicechat_reimagined`, ветка `main` (локально её же содержит ветка `rewrite-sfu`).

| Часть | Где | Что важно знать |
|---|---|---|
| Сервер | `cmd/server`, `internal/*` (Go 1.24+) | Один бинарник. HTTP(S) + WebSocket `/ws` + SFU на pion (голос и видео идут через сервер). SQLite в папке данных. |
| Фронтенд | `web/static` (vanilla JS, ES-модули, без сборки) | Встроен в бинарник через `go:embed`. Для разработки: `-web-dir web/static`. |
| TLS | `internal/cert/selfsigned.go`, `cmd/server/main.go` | По умолчанию **самоподписанный** сертификат: `<data>/selfsigned.crt/.key`. Ещё возможны Let's Encrypt (`-domain`) и свои файлы. |
| Доступ | `internal/app/access.go` | Ключи-приглашения. Веб-ссылка вида `https://host:port/#k=<ключ>`. Ключ хранится в `localStorage` (`z228.password`). Админ входит без ключа по своему токену. |
| Прод-сервер | VPS (адрес — у владельца, в репозиторий не пишем), сайт `https://<адрес>:3443`, голос UDP/TCP `50000` | systemd-сервис `z228`. **На VPS есть другие важные процессы (xray на 443/8443): их не трогать.** Деплой: собрать `GOOS=linux`, `scp` в `/tmp`, `install` в `/usr/local/bin/z228`, `systemctl restart z228`. |

### Нужные места во фронтенде

- `web/static/js/app.js`:
  - `toggleMute()` и `toggleDeafen()` — функции модуля (не экспортированы).
  - Push-to-talk: `S.settings.pushToTalk`, `S.settings.pttKey` (код клавиши `KeyboardEvent.code`).
    Обработчики `keydown`/`keyup` в `bindUi()` вызывают `voice.setPttHeld(true/false)`. На `blur` окна —
    `setPttHeld(false)`.
  - Настройки: `openSettings(section)`, разделы рисуются функциями `settingsVoice`, `settingsAdmin` и т.п.,
    помощники `toggleRow(...)`, `h(...)`.
  - Состояние: `S.muted`, `S.deafened`, `voice.active`, `voice.channelId`, `S.speaking` (Set id говорящих),
    `S.me.id`. Хук `onSpeaking` в конструкторе `Voice`.
- `web/static/js/voice.js`: `setPttHeld(held)`, `micOpen()`, `applyMicGate()`, звуки интерфейса `sfx(kind)`.

## 4. Строка-приглашение и проверка сервера

### 4.1. Формат
```
z228://<host>:<port>/?fp=<SPKI-SHA256-base64url>&k=<ключ-доступа>&n=<название>
```
- `fp` — SHA-256 от **SubjectPublicKeyInfo** (DER) сертификата сервера, base64url без `=`.
  Отпечаток именно SPKI, а не всего сертификата: при перевыпуске сертификата с тем же ключом он не меняется.
- `k` — ключ-приглашение (может отсутствовать, если сервер открыт).
- `n` — название сервера для окна и трея (необязательно).
- Если у сервера доверенный сертификат (Let's Encrypt), `fp` можно не указывать.

Кроме `z228://`, приложение принимает и веб-ссылку `https://host:port/#k=...` плюс отдельное поле для
отпечатка (запасной вариант: «отдельные поля»).

### 4.2. Проверка при первом запуске (Rust)
1. Разобрать строку.
2. Подключиться по TLS к `host:port` (rustls со своим `ServerCertVerifier`): взять сертификат, посчитать
   SHA-256 от его SPKI и сравнить с `fp`. Если не совпало — понятная ошибка «это не тот сервер или сертификат
   сменился». Хост для имени в TLS — IP-адрес, проверка имени не нужна: доверие держится на пине.
3. Сделать `GET /` и убедиться, что это z228 (в HTML есть `<title>ZALUPA228` или другой маркер; лучше добавить
   `GET /api/info` → `{"app":"z228","name":...}`, см. §8).
4. Сохранить в config: `{ "server": "host:port", "spki": "...", "name": "..." }`. **Ключ в config не хранить**:
   открыть главное окно с `https://host:port/#k=<ключ>`. Сайт сам запомнит ключ в `localStorage` и уберёт его
   из адреса.

### 4.3. Самоподписанный сертификат внутри WebView2
WebView2 по умолчанию не откроет сайт с самоподписанным сертификатом. Решение:
**обработчик `ServerCertificateErrorDetected`** (`ICoreWebView2_14`, через `WebviewWindow::with_webview` →
`webview2-com`):
- для хоста и порта из config: получить сертификат (`ICoreWebView2Certificate::ToPemEncoding`), посчитать SPKI
  SHA-256 и при совпадении с пином выставить `COREWEBVIEW2_SERVER_CERTIFICATE_ERROR_ACTION_ALWAYS_ALLOW`;
- во всех остальных случаях — `CANCEL`.

Запасной вариант (если обработчик недоступен): флаг Chromium
`--ignore-certificate-errors-spki-list=<base64 SPKI>` через `additionalBrowserArgs`. Но обработчик
предпочтительнее: он пинит только наш хост.

### 4.4. Смена сертификата
Если пин перестал совпадать (сервер перевыпустил ключ), показать окно `connect` с ошибкой и попросить новую
строку-приглашение. **Молча доверять новому сертификату нельзя.** Чтобы такое случалось редко, сервер должен
сохранять ключ при перевыпуске (§8.2).

## 5. Глобальные клавиши

### 5.1. Реализация
- **Низкоуровневые хуки Windows** `WH_KEYBOARD_LL` и `WH_MOUSE_LL` (крейт `windows`) в отдельном потоке
  со своим циклом сообщений.
- **Никогда не «съедать» события**: всегда `CallNextHookEx`. Клавиша рации должна доходить и до игры (как в
  Discord). Поэтому **не** использовать `tauri-plugin-global-shortcut`/`RegisterHotKey`: они перехватывают клавишу.
- Колбэк хука должен быть мгновенным: только положить событие в канал. Если колбэк думает дольше
  `LowLevelHooksTimeout` (~300 мс), Windows молча снимает хук. Добавить сторожа: если хук перестал присылать
  события, переустановить его.
- Кнопки мыши: `WM_XBUTTONDOWN/UP` (`XBUTTON1` = Mouse4, `XBUTTON2` = Mouse5); средняя кнопка — по желанию.
- Комбинации: модификаторы (Ctrl/Shift/Alt) + клавиша. Для рации обычно одна клавиша; комбинации нужны мьюту
  и оглушению.
- Автоповтор клавиши (повторный `keydown` без `keyup`) не должен дёргать рацию.

### 5.2. Действия
| Действие | Тип | По умолчанию **[по умолчанию]** |
|---|---|---|
| Рация | удержание | не назначена |
| Мьют | переключение | не назначена |
| Оглушение | переключение | не назначена |

- **Задержка отпускания рации:** 150 мс по умолчанию, настраивается от 0 до 1000 мс. Иначе съедается конец слова.
- **Звук рации** (по решению заказчика): тихий короткий щелчок на нажатие и отпускание; выключается в
  настройках. Играть его в странице через `sfx()` (добавить виды `ptt-on`/`ptt-off`), чтобы звук шёл тем же
  устройством вывода, что и голос.

### 5.3. Ограничения (написать в интерфейсе)
- Если игра запущена **от администратора**, хуки обычного процесса не видят её ввод (UIPI). Решение: запускать
  ZALUPA228 тоже от администратора. Показать подсказку, если после назначения клавиши события не приходят.
- Некоторые античиты могут ругаться на низкоуровневые хуки. Discord использует то же самое, так что обычно это
  нормально, но упомянуть стоит.

### 5.4. Назначение клавиш
В веб-настройках (раздел «Приложение», виден только в десктопе, §7): кнопка «Назначить» → страница вызывает
`desktop_record_binding(action)` → Rust ловит следующее нажатие клавиши или кнопки мыши (`Esc` отменяет) →
сохраняет в config → возвращает человекочитаемое имя («Mouse4», «Ctrl+Shift+M», «V»).

## 6. Трей и окно

- Закрытие крестиком → `hide()` вместо выхода. При первом сворачивании один раз показать уведомление
  «ZALUPA228 работает в трее».
- **Один экземпляр** (`tauri-plugin-single-instance`): второй запуск показывает уже открытое окно.
- Меню трея: «Открыть», «Мьют», «Оглушение», «Сменить сервер…», «Проверить обновления», «Выход».
- Клик по иконке открывает окно.
- **Иконка по состоянию** (по решению заказчика), состояние присылает страница (§7):
  - серая — не в голосе;
  - обычная (логотип) — в голосе;
  - с зелёной точкой или обводкой — **передаю** (микрофон открыт и есть речь, либо зажата рация);
  - с красной точкой — мьют или оглушение.

  Подсказка у иконки: «ZALUPA228 — <канал> · мьют».
- Иконки сгенерировать из `web/static/icon-512.png` (настоящий PNG; `logo.png` на самом деле JPEG).
- **Фон и производительность:** скрытое окно **не** усыплять (`TrySuspend` не вызывать). Голос должен
  продолжать работать в трее. Страница при скрытой вкладке сама отписывается от видео (`document.hidden`) —
  это правильно и экономит процессор. Проверить, что звук и рация в трее работают.

## 7. Мост Rust ↔ страница

### 7.1. Rust → страница (события)
Через `webview.eval(...)`:
```js
window.dispatchEvent(new CustomEvent("z228-desktop", { detail: { type: "ptt", down: true } }));
// type: "ptt" {down}, "mute-toggle", "deafen-toggle", "update-available" {version, notes}, "update-progress" {pct}
```

### 7.2. Страница → Rust (команды)
`window.__TAURI__.core.invoke(...)`. Origin сервера задаётся пользователем, поэтому **capability для удалённого
URL добавляется во время работы**: `AppHandle::add_capability` с `remote.urls = ["https://<host>:<port>/*"]` и
только нашими командами. В статическом конфиге — `app.withGlobalTauri: true`.

| Команда | Аргументы | Что делает |
|---|---|---|
| `desktop_info` | — | `{version, bindings, pttReleaseMs, pttSound, server}` |
| `desktop_report_state` | `{inVoice, channel, muted, deafened, transmitting}` | обновить иконку и подсказку трея; страница шлёт при изменении, не чаще 10 раз в секунду |
| `desktop_record_binding` | `{action}` | поймать следующее нажатие, сохранить, вернуть имя |
| `desktop_clear_binding` | `{action}` | снять клавишу |
| `desktop_set_options` | `{pttReleaseMs, pttSound}` | сохранить |
| `desktop_change_server` | — | открыть окно `connect` |
| `desktop_check_update` / `desktop_install_update` | — | ручная проверка и установка |

### 7.3. Изменения в `web/static` (делает этот же агент)
1. **Новый модуль `js/desktop.js`**, подключается из `app.js`:
   - `isDesktop = !!window.__TAURI__` (Rust дополнительно задаёт `window.z228Desktop = {version}` через
     initialization script);
   - слушает `z228-desktop`: `ptt` → `voice.setPttHeld(down)` (с задержкой отпускания), `mute-toggle` →
     `toggleMute()`, `deafen-toggle` → `toggleDeafen()`;
   - отправляет `desktop_report_state` при изменении состояния.
2. **`app.js`:**
   - передать в `desktop.js` нужные функции (`toggleMute`, `toggleDeafen`, доступ к `voice`, `S`);
   - если в десктопе назначена клавиша рации, включить режим рации (`S.settings.pushToTalk = true`) и
     **отключить веб-обработчики `keydown`/`keyup` для рации**, чтобы не было двойного срабатывания;
   - **не** сбрасывать рацию на `window.blur`, когда работает десктопная рация (в игре окно чата всегда без
     фокуса);
   - новый раздел настроек «**Приложение**» (только в десктопе): клавиши трёх действий («Назначить» /
     «Снять»), задержка отпускания, звук рации, «Сменить сервер», версия и «Проверить обновления»;
   - звуки `ptt-on` / `ptt-off` в `sfx()`.
3. Разделы «Режим рации» в обычных настройках голоса в десктопе заменить подсказкой «Клавиши — в разделе
   Приложение».

## 8. Изменения на сервере (Go)

1. **Отпечаток сертификата в админке.** В `cmd/server/main.go` после выбора `tlsConf` посчитать SPKI SHA-256
   leaf-сертификата (для autocert отпечаток не нужен — пусто) и передать в `app.Options`. Админская
   WS-команда `desktop-invite {code}` возвращает `{spki, name}`. Блок в «Администрирование»:
   **«Ссылка для десктопа»** — выбрать ключ-приглашение (или «без ключа», если сервер открыт), собрать
   `z228://<location.host>/?fp=…&k=…&n=…`, кнопка «Копировать».
2. **Стабильный ключ сертификата.** `cert.LoadOrCreate` сейчас при перевыпуске (новый IP в SAN, истечение)
   генерирует **новый** ключ, и пин в десктопе ломается. Нужно переиспользовать существующий
   `selfsigned.key`, если он читается, и менять только сертификат.
3. `GET /api/info` → `{"app":"z228","name":..., "version":...}` без авторизации: для проверки «это наш сервер».
4. Ничего из существующего не ломать: веб-версия должна работать как раньше.

## 10. WebView2: разрешения и флаги

- Микрофон, камера, экран: обработчик `PermissionRequested` → для origin из config автоматически разрешать
  `Microphone`, `Camera`; для остального — запрет. Демонстрация экрана (`getDisplayMedia`) в WebView2 показывает
  свой выбор окна; проверить, что работает.
- **Автовоспроизведение:** `--autoplay-policy=no-user-gesture-required` в `additionalBrowserArgs`, чтобы после
  автовозврата в голос (сайт так умеет) звук играл без клика.
- Папка данных WebView2 — стандартная Tauri (`%LOCALAPPDATA%\<identifier>`): там живут `localStorage`, ник,
  ключ и настройки звука.
- `identifier`: **[по умолчанию]** `ru.zalupa228.desktop`, `productName`: `ZALUPA228`.

## 12. Критерии готовности

Проверять на Windows 11 с реальным VPS (`https://<адрес>:3443`) или локальным сервером
(`go run ./cmd/server -web-dir web/static`).

1. Первый запуск: вставить `z228://…` из админки → окно открывает сайт **без** предупреждения о сертификате,
   вход по ключу проходит.
2. Неправильный `fp` → понятная ошибка, сайт не открывается. Подмена сертификата сервера → то же самое.
3. В игре (окно игры в фокусе, оконный/borderless режим):
   - рация на клавише и на Mouse4 открывает микрофон, пока зажата; звук рации слышен; конец фразы не
     обрезается (задержка 150 мс);
   - клавиша рации **доходит до игры** (не перехватывается);
   - мьют и оглушение переключаются, состояние совпадает с кнопками на сайте.
4. Закрытие окна → приложение в трее, голос продолжает работать, рация работает. Иконка трея меняется:
   не в голосе / в голосе / передаю / мьют.
5. Второй запуск exe открывает существующее окно.
6. Выпущен тег `desktop-v0.1.1` → установленная `0.1.0` находит обновление, ставит по согласию и
   перезапускается.
7. Веб-версия в обычном браузере работает как раньше (регрессия): smoke-тест
   `go run ./tools/smoketest -url ws://127.0.0.1:3000/ws -admin <пароль>`.
8. Простой: процесс приложения (без WebView2) потребляет ~0% CPU; хуки не вызывают задержек ввода в играх.

## 13. Задел на потом (не делать в MVP)

  `speaking`. Работает только в оконном/borderless режиме игр. Сейчас просто держать состояние в Rust в такой
  форме, чтобы оверлею было что рисовать.
- Автозапуск с Windows (`tauri-plugin-autostart`), стартовать свёрнутым в трей.
- `z228://`-ссылки по клику (deep link) вместо вставки строки.
- Linux (`.AppImage`) и macOS.

## 14. Известное и оговорки

- В веб-версии есть **не воспроизведённый баг**: у заказчика иногда не печатается текст в поля админки
  (ключи, роли). У нас воспроизвести не удалось. Если увидите его в WebView2 — сообщите.
- Пароль root VPS засветился в переписке. Доступ к VPS — только по SSH-ключу. Деплой сервера — только сервиса
  `z228`, **другие процессы на VPS не трогать**.
- Сервер на Windows-машине заказчика может работать в режиме Radmin (`scripts\start-radmin.bat`). Десктоп
  должен работать и с таким сервером: в строке-приглашении будет Radmin-IP `26.x.x.x`.
