# z228

Самохостный голосовой чат в стиле Discord: текстовые и голосовые каналы, демонстрация экрана,
реакции, ответы, файлы, громкость каждого участника. Один бинарник без внешних зависимостей:
SQLite внутри, фронтенд встроен.

## Как это работает

- **Голос идёт через сервер (SFU на [pion](https://github.com/pion/webrtc))**, а не напрямую между людьми.
  Каждый участник держит одно соединение с сервером. Поэтому не нужны ни Radmin, ни TURN:
  если открывается сайт и доступен порт голоса, звук тоже будет.
- Весь звук и экран идут через **один порт** (по умолчанию `50000`, UDP и TCP как запасной вариант).
- Данные (БД, загрузки, сертификат) лежат в папке `data/`.

## Быстрый старт на Windows

Нужен [Go](https://go.dev/dl/) 1.24+ (`winget install GoLang.Go`).

| Что | Как |
|---|---|
| Обычный запуск | двойной клик по `scripts\start.bat` |
| Игра по Radmin VPN | двойной клик по `scripts\start-radmin.bat` |
| Пересобрать | `powershell -File scripts\build.ps1` (флаг `-linux` дополнительно соберёт бинарник для VPS) |

При первом запуске Windows спросит про брандмауэр. Разрешите доступ **в частных и общественных сетях**
(Radmin считается общественной сетью).

В консоли сервер покажет готовые ссылки для друзей:

```
  Этот ПК:      http://localhost:3000
  Radmin VPN:   https://26.48.124.88:3443
  Локалка:      https://192.168.1.179:3443
  Интернет:     https://93.184.216.34:3443   (если проброшены порты)
  Пароль админа (сгенерирован, сохранён в БД): d8c8ecef515f
```

Сертификат самоподписанный: браузер один раз предупредит, нажмите «Дополнительно» → «Перейти на сайт».
HTTPS нужен потому, что браузер не даёт доступ к микрофону по HTTP (кроме `localhost`).

## CLI

```
z228 [флаги]

  -radmin            режим Radmin VPN: ссылка по Radmin-IP, внешний IP не определяется
  -lan               только локалка/VPN, внешний IP не определяется
  -open              открыть чат в браузере
  -port 3000         HTTP-порт
  -https-port 3443   HTTPS-порт (0 — выключить, например за reverse proxy)
  -rtc-port 50000    порт голоса (UDP + TCP)
  -data ./data       папка данных
  -name ZALUPA228    название сервера
  -slogan "..."      подпись под названием в шапке
  -password ...      пароль для входа на сервер (по умолчанию без пароля)
  -admin-password .. пароль администратора (по умолчанию генерируется и сохраняется)
  -public-ip a,b     дополнительные адреса для голоса (внешний IP, IP VPN), через запятую
  -domain chat.example.com   свой домен + бесплатный сертификат Let's Encrypt
  -version
```

У каждого флага есть переменная окружения: `PORT`, `HTTPS_PORT`, `RTC_PORT`, `DATA_DIR`, `SERVER_NAME`,
`SERVER_SLOGAN`, `SERVER_PASSWORD`, `ADMIN_PASSWORD`, `RTC_PUBLIC_IP`, `TLS_DOMAIN`, а также `TLS_CERT_FILE`/`TLS_KEY_FILE`
(свой сертификат), `TLS_EMAIL`, `CERT_EXTRA_IPS`, `MAX_UPLOAD_MB` (по умолчанию 25), `RTC_AUTO_PUBLIC_IP`,
`RTC_STUN_SERVER`, `LISTEN_HOST`, `WEB_DIR` (отдавать фронтенд с диска, для разработки: `-web-dir web/static`).

## Друзья из интернета (без Radmin)

На домашнем ПК пробросьте в роутере на свой компьютер:

- **TCP 3443**: сайт;
- **UDP 50000** и **TCP 50000**: голос и экран.

Внешний IP сервер определяет сам и сообщает клиентам. Если у провайдера CGNAT (серый IP),
проброс не поможет: нужен VPS или Radmin.

### VPS (Linux)

```bash
./z228-linux -domain chat.example.com -port 80 -https-port 443
```

Откройте TCP 80 и 443 и UDP/TCP 50000. Сертификат Let's Encrypt получится автоматически.
Либо через Docker: `docker compose up -d --build` (см. комментарии в `docker-compose.yml`).

### За reverse proxy (Caddy/nginx)

Запустите с `-https-port 0`, проксируйте HTTP и WebSocket (`/ws`) на `:3000`.
Порт голоса проксировать не нужно, его надо открыть напрямую.

## Доступ только по приглашению

Пока ключей нет, зайти может любой, кто знает адрес. Чтобы закрыть сервер от посторонних и ботов,
откройте «Настройки → Администрирование → Доступ к серверу» и создайте ключ. Появится ссылка вида
`https://сервер:3443/#k=ключ`: по ней человек заходит, ключ запоминается в браузере и пропадает
из адресной строки. Сделайте отдельный ключ на каждого: тогда одному человеку можно отозвать доступ,
не трогая остальных. Отзыв сразу отключает всех, кто вошёл по этому ключу.

- Без ключа сервер не пускает ни в чат, ни в голос. Порт голоса без входа в чат бесполезен:
  он принимает только соединения, которые сервер сам выдал вошедшим.
- После 8 неверных попыток ключа или пароля админа за 10 минут IP блокируется на 15 минут.
- Админ (браузер, где выполнен вход в админку) заходит без ключа, поэтому запереть себя нельзя.
- Есть и общий ключ на весь сервер: `-password` или `SERVER_PASSWORD`.

## Возможности

- Текстовые каналы: история в SQLite, подгрузка при прокрутке, ответы, правка (↑ в пустом поле),
  удаление, реакции, упоминания `@ник` с автодополнением, разметка (`**жирный**`, `*курсив*`, `__подчёркнутый__`,
  `~~зачёркнутый~~`, `||спойлер||`, `` `код` ``, блоки кода, цитаты), файлы и картинки (вставка из буфера,
  перетаскивание), индикатор «печатает…», непрочитанные и упоминания на каналах.
- Голосовые каналы: участники видны в списке каналов, подсветка говорящего, свой мьют/«оглушение»,
  push-to-talk, выбор микрофона и динамиков, шумо- и эхоподавление, проверка микрофона, звуки входа и выхода,
  пинг до сервера, автоматическое переподключение.
- **Громкость каждого участника 0–200% и локальный мьют**: клик по участнику в голосовом канале,
  на плитке или в списке. Настройки запоминаются по нику.
- Демонстрация экрана (720p–1440p, до 60 FPS) с полноэкранным просмотром.
- Администратор (пароль в консоли сервера → «Настройки → Администрирование»): создание,
  переименование, порядок и удаление каналов, **серверный мьют** (сервер перестаёт пересылать звук
  человека всем), отключение от голоса, кик, удаление любых сообщений.
- Светлая и тёмная тема, мобильная раскладка, уведомления на рабочем столе об упоминаниях.

## Разработка

```bash
go run ./cmd/server -web-dir web/static -lan     # фронтенд читается с диска, правки видны после F5
go run ./tools/smoketest -url ws://127.0.0.1:3000/ws -admin <пароль> [-key <ключ>]   # проверка чата, голоса через SFU и серверного мьюта
```

Структура: `cmd/server` (CLI и HTTP), `internal/app` (WebSocket-протокол, загрузки), `internal/sfu` (голос),
`internal/store` (SQLite), `internal/netinfo` (адреса, Radmin, внешний IP), `web/static` (фронтенд без сборки).
